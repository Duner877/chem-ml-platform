# V0.7 已知限制（Known Limitations）

如实记录，不做伪装。本文件随每个 Phase 更新。

## 硬件 / 外部依赖
1. **GPU**：仓库默认 CPU 版 PyTorch。CUDA 加速需用户自行安装与本机驱动匹配的 CUDA 版 torch（不在安装包内捆绑，避免版本不兼容）。无 GPU 时 GPU 节点返回 `GPU_UNAVAILABLE` 并明确标注实际执行设备，绝不虚报加速。
2. **商业与外部计算软件**（Gaussian、Materials Studio、ORCA、GROMACS、LAMMPS、ABACUS、CPMD）：本仓库内置输入文件生成与物理回退引擎（EHT / Lennard-Jones / 紧束缚）。真实软件未安装时相关集成测试标记为回退路径验证，不算真实集成测试。Materials Studio 为图形化商业软件，不提供通用 CLI 伪装接口。
3. **真实 LLM Provider**：需要用户自备 API Key。无 Key 时使用内置离线推理器（诚实降级，来源标注为 offline），相关云端测试跳过。
4. **RDKit**：分子 2D 结构图在 RDKit 可用时使用 RDKit 渲染；不可用时该节点返回 `DEPENDENCY_MISSING` 与安装指引，不使用假结构图。

## 平台
5. **Electron 桌面构建**：Windows 构建在本机验证；Linux/macOS 提供构建配置但未在对应平台实测（如实标注 unverified）。
6. **插件隔离**：第三方插件默认在独立子进程中执行；受限于 Python 子进程模型，完全的内存隔离不可行，文档明确要求用户只安装可信来源插件。
7. **厂商原始格式**（Thermo RAW、Bruker 等）：仅识别与提示转换流程，不宣称解析——解析需官方 SDK/授权。
8. **Node SDK 测试**：node_sdk/nodejs 的 npm test 未纳入本机质量门禁必跑集（需 Node 环境，结果在发布报告中如实标注）。

## 设计取舍
9. **缓存**：节点级缓存默认关闭（v0.6 行为保留），缓存键已含节点类型+参数+输入摘要；v0.7 追加节点版本维度。
10. **Provenance 渐进覆盖**：引擎自动记录通用字段（时间/参数/状态/环境/缓存）；provider/model/device/fallback 等字段依赖节点以约定属性暴露，v0.6 存量节点多数尚未填充（缺省为空，不伪造）。
11. **不同结论置信度不平均**：证据面板区分实测/计算/预测/假设，不提供跨来源的简单加权平均（无统计依据）。

## v0.7.1 科学基准暴露的限制（任务 I，见 `V07_1_BENCHMARK.md`）
12. **单通道置信度未做跨候选标定**：仅有一路证据（如只有 IR）时，节点在该通道内归一化，最高分者恒为 1.0，因此**单通道配置的平均置信度不具备概率意义**（基准中 IR-only 平均置信度 1.000 但 Top-1 仅 0.375）。多模态下该问题被稀释，但**置信度仍不应被解读为概率**。
13. **跨来源退化**：当参考库来自经验/文献碎片而观测谱来自模型预测时（基准 `curated` 参考库），多模态 Top-1 从闭环 1.000 降至 **0.917**（24 例中 2 例失败：nicotine、histidine）。这属于参考库判别力限制，已记录于基准报告第 5 节。
14. **基准样本为平台正向模型生成，非独立实验数据**：`datasets/` 与参考库均为 CC0 合成数据。因此该基准验证的是**检索/排序流水线**（软件测试 + 数值验证），**不构成科学结果验证**（任务 I.4）。真实测量数据的端到端验证留待 v0.8。
15. **评测集规模 24**：任务书建议 50–100 个样本，实际规模受**可核验来源**限制——当前离线库仅含 24 个经 PubChem 核对分子式/质量的化合物，未人为扩充。
16. **MS 通道依赖参考碎片列表**：鉴定节点的质谱通道需要候选条目提供碎片 m/z；仅提供 SMILES 的外部候选库无法参与 MS 打分（v0.7.1 已支持从表列解析碎片/IR/Raman/UV 列表）。

## v0.7.1 工程限制
17. **DOCX 导出需要 `python-docx`**：`ReportExportNode` 的 `docx` 格式依赖该可选包；缺失时节点抛出明确错误，绝不写入伪造文档。
18. **Electron 安装包未在本环境构建**：质量门禁的 `electron_installer_artefact` 在有安装产物时 PASS，否则如实 SKIP（需在构建主机执行 `npm run dist`）。干净机安装测试未在本次环境完成。
19. **质量门禁中的 SKIP 不计为 PASS**：前端类型检查/生产构建在未安装 `node_modules` 时 SKIP；GPU 检查在无 CUDA 时 SKIP，均单独计数。
20. **Provenance schema 版本独立**：`provenance/schema.py` 的 `PROVENANCE_SCHEMA_VERSION` 为 schema 版本（0.7.0），与产品版本 0.7.1 解耦，属有意设计。
